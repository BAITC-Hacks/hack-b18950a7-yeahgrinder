# Проверка SupplyAI для другого участника команды

Этот набор объединяет backend из `main` и frontend в корне репозитория. Рекомендуется Python 3.12 (минимум 3.11), Node.js 20+ (минимум 18 для модульных JS-тестов). Ключи OpenAI/NVIDIA не нужны. Набор автоматически отключает вызовы платных моделей и трассировку; тесты агента используют подготовленные ответы модели.

Проверено 23.09.2026 на macOS, Python 3.12.14 и Node.js 24.11.1 с обоими приложенными ZIP: **69 passed, 0 failed, 0 skipped**, около 51 секунды. Есть предупреждения библиотек об устаревающих API; платные AI-вызовы и клики в браузере в этот результат не входят.

## 1. Подготовить окружение

Из корня актуального проекта:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
node --version
```

На Windows используйте `py -3.12 -m venv .venv`, затем `.venv\Scripts\python.exe` вместо `.venv/bin/python` и `.venv\Scripts\uvicorn.exe` вместо `.venv/bin/uvicorn`. Команды с переносами `\` вводите одной строкой.

## 2. Быстрая проверка без приватных файлов

```bash
.venv/bin/python scripts/test_project.py
```

Проверяет синтетические сценарии движка, загрузчик, сервис и SQLite, API, инструменты агента, frontend data provider и генерацию XLSX. Семь интеграционных тестов реальных ZIP будут явно отмечены `SKIPPED`: это не полный прогон.

## 3. Полная проверка с архивами

Передайте оба архива участнику отдельно. Они не включаются в git. Имена файлов могут содержать пробелы — обязательны кавычки.

```bash
.venv/bin/python scripts/test_project.py \
  --iek-zip "/путь/к/IEK (1).zip" \
  --se-zip "/путь/к/Systeme electric (1).zip"
```

Для текущего компьютера:

```bash
.venv/bin/python scripts/test_project.py \
  --iek-zip "$HOME/Downloads/IEK (1).zip" \
  --se-zip "$HOME/Downloads/Systeme electric (1).zip"
```

Первый прогон читает большие XLSX и может занять несколько минут. Код возврата `0` означает успех, ненулевой — ошибка теста или окружения. JUnit XML сохраняется в `reports/pytest.xml`; другой путь: `--report reports/my-run.xml`. Полный успех — нет `FAILED`/`ERROR`, ZIP-тесты не пропущены. Отдельные предупреждения об устаревающих API библиотек не равны проваленным тестам.

Тесты извлекают только XLSX в временную папку pytest. `__MACOSX`, служебные файлы, документы и инструкции из архивов игнорируются. Искажённые имена заменяются нейтральными — тип источника определяется по заголовкам таблиц. `data/raw`, рабочая SQLite, текущие расчёты и исходные ZIP не меняются. После тестов приватные копии могут оставаться во временных папках pytest до его обычной очистки; не публикуйте их.

## Что именно проверяется

| Область | Проверки |
|---|---|
| Архивы | По 6 XLSX на поставщика, 6 типов источников; служебные файлы пропускаются; пути вне папки запрещены; рабочие файлы не перезаписываются |
| Реальная загрузка | IEK + Systeme Electric, снимок 22.09.2026, 3 561 товар, 33 месяца остатков, единицы, положительный спрос без возвратов, сезонность, отсутствие молча потерянных источников |
| Движок | Транзит, остатки, категории, кратность, сезонность, восстановление спроса, редкий спрос, неполный месяц, устойчивый рост; каждая рекомендация имеет обоснование |
| LOOP | Реальная накладная 210 000 шт. от 09.06.2025 остаётся в исходных данных и отражается как исключённая в расчёте и UI |
| Сценарии | Прирост +20% увеличивает прогноз; what-if с поступлением уменьшает потребность и не меняет сохранённый расчёт |
| API | Запуск → фильтры → карточка → ручная правка → утверждение → корректный XLSX; неизвестные ресурсы/плохие параметры; чат без ключа возвращает 503 |
| Связь с frontend | `/` и JS/CSS доступны с правильным MIME; `/ui/data` соответствует расчёту, имеет корректный JSON и графики; приватные backend-файлы не раздаются |
| JS-модули | Один fetch для данных, fallback на демо при ошибках сети/HTTP/JSON, XLSX с числовыми количествами и листом утверждения |
| Агент | Безопасные инструменты, SQL только для чтения, проверка чисел, отказ от отправки заказа; без запросов к реальной LLM |

Проверки даты, числа SKU и LOOP закреплены за приложенными сентябрьскими выгрузками 2026 года. Для нового снимка сначала проверьте изменения источников и обновите ожидаемые значения в `tests/test_partner_archives.py`. Не ослабляйте проверки только ради зелёного результата.

## 4. Проверка интерфейса вручную

Автотесты выше не кликают браузер и не заменяют визуальную проверку. Для просмотра реальных данных подготовьте отдельную папку (команда откажется перезаписывать существующую):

```bash
.venv/bin/python -m scripts.fixture_archives \
  --iek-zip "/путь/к/IEK (1).zip" \
  --se-zip "/путь/к/Systeme electric (1).zip" \
  --output data/raw
.venv/bin/uvicorn api:app --host 127.0.0.1 --port 8000
```

Если `data/raw` уже существует, используйте новую папку внутри `data/raw/`, например `--output data/raw/qa-snapshot`, и запустите сервер с `DATA_DIR="$PWD/data/raw/qa-snapshot" .venv/bin/uvicorn api:app --port 8000`.

В PowerShell сначала задайте `$env:DATA_DIR = "$PWD/data/raw/qa-snapshot"`, затем запустите `.venv\Scripts\uvicorn.exe api:app --port 8000`.

Откройте http://127.0.0.1:8000 и http://127.0.0.1:8000/docs.

| Шаг | Ожидаемый результат |
|---|---|
| Открыть обзор | Реальные данные; оба поставщика; отсутствие сообщения о демо-fallback |
| Открыть закупки, выбрать поставщика/категорию/транзит, найти несуществующий артикул | Фильтры применяются, пустое состояние понятно, сброс возвращает товары |
| Найти LOOP по названию или `130200305_` | В карточке и архивном графике видна продажа 210 000 шт.; есть объяснение исключения |
| Открыть товар с восстановленным спросом | Факт и скорректированный спрос различаются, есть причина и период |
| Изменить два количества, переключить фильтры, перезагрузить страницу | Правки сохраняются локально, рекомендация видна отдельно |
| Выбрать позиции и добавить в черновик | Правильные поставщики, единицы и количества; нет случайных лишних позиций |
| Утвердить без ФИО / без отметки о проверке | Подтверждение недоступно |
| Ввести ФИО, подтвердить, скачать XLSX и CSV | Только положительные утверждённые количества; в XLSX есть лист «Утверждение» |
| Изменить подтверждённый черновик | Подтверждение сброшено, требуется повторная проверка |
| Применить +20%, открыть данные и оговорки | Понятен выбранный сценарий; графики/срочность обозначены как базовые |
| Проверить узкое окно, Tab и Escape | Навигация доступна, панели закрываются, текст/кнопки не перекрыты |

В текущем frontend решения сохраняются **локально в браузере**, а `/runs/.../decisions` хранит решения backend отдельно. Автотесты проверяют оба пути отдельно: UI ещё не синхронизирует локальное утверждение с серверной SQLite. Ничего не отправляется поставщикам.

## Отчёт об ошибке

Передайте участнику: commit (`git rev-parse --short HEAD`), версии Python/Node, команду, имена архивов, имя упавшего теста, текст ошибки и `reports/pytest.xml`. Для UI — шаги, ожидаемое/фактическое поведение, скриншот и ошибку из консоли. Не прикладывайте `.env`, ключи или исходные выгрузки в публичные issue.
