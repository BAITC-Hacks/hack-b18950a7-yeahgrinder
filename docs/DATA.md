# Данные партнёра

Два поставщика, склад один — Алматы. Каждый архив распаковывается в свою папку
(в git не коммитим: данные партнёра):

- `IEK.zip` → `data/raw/IEK/`
- `Systeme electric.zip` → `data/raw/SE/` (папку `__MACOSX` не распаковывать). Имена файлов
  в архиве искажены (macOS + CP866) — **переименовывать не нужно**: если файл не нашёлся по имени,
  загрузчик узнаёт его по заголовкам колонок.

Загрузчик сам находит поставщиков по подпапкам и файлы — по началу имени.

# ИЭК: IEK.zip

Поставщик — ИЭК (IEK/ITK). Ключ для связи файлов —
**код 1С** (вида `010500008_`). Во всех файлах в конце есть строка «Итого» — выкидывать.

## Особенности и подводные камни

- **Количество в продажах положительное** (расход). 115 строк с минусом — старые 2023 г.
  и возвраты; 3+3 строки «Приходная накладная» / «Заказ покупателя» — мусор, отфильтровать.
- **Единицы разные**: шт / м / упак. Не суммировать между SKU без учёта единиц.
- **Реальный разовый выброс**: 09.06.2025, накладная 20000064179, «Петля металлическая
  LOOP» (130200305_) — **210 000 шт** одной строкой. Из-за неё июнь 2025 по всей компании
  = 402 тыс. шт против обычных ~200 тыс. Идеальная демонстрация must-have №4.
  Другие крупные строки (ВА47-29 25А — 7 488 шт, трубы — 3–4 тыс. м) — кандидаты на проверку.
- **Нет ID клиента и нет цены** в строках продаж, хотя кейс их упоминает. Разовые заказы
  выявляем по размеру строки/накладной относительно типичной для SKU, а не по клиенту.
  Вопрос партнёру: можно ли получить обезличенный ID контрагента.
- **Нет явного файла stockout.** Выводим сами: месяц с нулевым/пустым начальным остатком
  у SKU с историей продаж + провалы в ежедневных продажах. В кейсе он назван входом —
  вопрос партнёру.
- **Текущий остаток** точно не известен: есть только начало сентября 2026, приходов нет.
  Оценка: остаток на 01.09 − продажи с 01.09 по 22.09 (+ пришедшее, если узнаем).
- **Сроки поставки** явно не даны, но выводятся из «Пути»: дата заказа → «поступление до».
  РФ-заказы ≈ 35–40 дней, прочие ≈ 12–24 дня.
- **Категорий нет отдельным полем.** Гипотеза: префикс кода 1С — товарная группа
  (все `0105xxxxx` — ВА47-29, `1303xxxxx` — гофротрубы). Проверить перед использованием.
- **Сезонность дана на уровне компании** в деньгах, не по SKU. Для SKU с короткой
  историей — брать её (или по группе), для SKU с 2 годами истории — считать свою.
- В названиях зашита упаковка: `(12/144)` = 12 в коробке / 144 в ящике.

# Systeme Electric: Systeme electric.zip

| Файл | Что внутри | Отличия от ИЭК |
|---|---|---|
| `Динамика продаж_Syseme Electric_2025-2026.xlsx` | 77 тыс. строк накладных, 565 SKU | формат тот же |
| `Ежемесячные продажи в кол-м выражении ...xlsx` | по месяцам 2024–2026 | есть колонки «Артикул», «Кратность» |
| `Ежемесячные остатки ...xlsx` | на 1-е число | первая колонка «№», код в 3-й |
| `Товар в пути_SystemElectric на 22.09.2026.xlsx`, лист `TDSheet` | **модель менеджера**: категория 2026, себестоимость «СС реал», продажи по месяцам, формулы «Ср мес», «Кэф. Роста», «Запас», остатки по локациям, пустая колонка «Заказ», «СЭ в пути 24.09» | заголовок во 2-й строке |
| `MOQ SystemElectric.xlsx` | «Кратность» | 554 SKU |
| `Сезонность ...xlsx` | коэффициенты по годам | нет блока «СРЕДНЯЯ СЕЗОННОСТЬ», есть колонка «СЕЗОННОСТЬ» |

- **Текущий остаток дан напрямую** (как у менеджера): свободный + витрина + ТЗ + розничный.
  У ИЭК — оценка по остатку на 1-е число.
- **Категории 1/2/3/5/7** из файла менеджера. 7 — новинка/выведен, автозаказа нет.
  У ИЭК категорий нет → ABC по числу строк накладных за 12 мес. (80/15/5%).
- **Себестоимость** есть → сумма заказа в ₸. У ИЭК цен нет.
- **Срок поставки**: дат заказа нет, только «в пути 24.09» → **45 дней — допущение**.
  У ИЭК — из дат заказов в пути: медиана, взвешенная по количеству, = 24 дня.
- **Регулярно крупные накладные**: «Установочная коробка IMT35100» (030200192_) уходит по
  60–90 тыс. шт. на накладную — это обычный спрос, не выброс. Правило: крупные строки
  в 3+ разных месяцах разовыми не считаются.
- Коды SE и ИЭК **не пересекаются**, но префиксы групп могут совпадать — группы считаем
  внутри поставщика.
- Сентябрь 2026 в файлах сезонности посчитан по 22 дням → досчитываем ×30/22.
